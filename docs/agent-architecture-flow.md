# Delegate 新架构：从用户输入到回答与执行

> 历史版本：最新完整流程见[目标架构 V2（2026-09-28）](agent-architecture-flow-v2.md)。本文保留讨论记录；入口控制、预算/恢复顺序、工具目录、最终核验和交付以V2及最新整改方案为准。

日期：2026-09-24。本文是目标架构，不是当前全部已上线的功能清单。复用已有 Pi 主循环、Broker、授权检索、数据库/Outbox、审批恢复、额度账本与 All-in-One；新增或改造任务理解、按需上下文、统一能力契约、分层复核及产物协议。

核心结构：一个主 Agent；服务端维护真实身份、任务、权限与操作状态；知识、记忆、Skill 和工具按任务加载；服务端硬校验始终执行，独立语义复核按需启用。

下图中的“识别、选择、规划、组织答案”是逻辑职责，同一主模型轮次可以承担多个职责，不表示每个方框都调用一次模型。路由只决定候选路径，不授予权限。所有会产生数据访问或外部效果的能力必须经过同一执行检查。

## 1. 整体主流程

```mermaid
flowchart TD
    U["用户输入<br/>文字、附件、继续、修改或取消"] --> E["渠道入口<br/>Web / Matrix / Telegram"]
    E --> V["入口校验<br/>渠道、会话、附件归属、请求去重"]
    V --> A{"代表已发布且渠道可用？"}
    A -->|否| STOP["返回真实不可用状态"]
    A -->|是| C["加载可信配置与运行状态<br/>身份、范围、权限、任务、额度"]
    C --> T["处理本轮与已有任务的关系<br/>详见图 2"]
    T -->|状态或取消等明确控制指令| D["服务端处理<br/>查询状态或停止可取消步骤"]
    T -->|需要理解和回答| S["范围与权限初筛<br/>不读取尚未获准的敏感正文"]
    S -->|受限或需验证身份| L["说明边界或发起身份验证"]
    S -->|允许继续| R["选择处理路径并按需组装上下文<br/>详见图 3、4"]
    R --> B{"模型调用预算可用？"}
    B -->|否| LIMIT["说明额度或预算限制"]
    B -->|是| M["主 Agent<br/>理解请求并选择下一步"]
    M -->|已有足够信息| ANSWER["组织候选答案"]
    M -->|缺少关键输入| ASK["提出必要澄清问题"]
    M -->|需要资料或行动| G["统一工具执行检查<br/>详见图 5"]
    G -->|允许| X["执行并持久化结果<br/>详见图 6"]
    G -->|需审批| WAIT["保存状态并暂停<br/>不执行待批准动作"]
    G -->|拒绝或条件缺失| O["返回结构化受限原因"]
    WAIT -->|获得有效审批并重验通过| X
    WAIT -->|拒绝、过期或取消| O
    X --> O
    O --> J{"还有相关、获准且预算允许的下一步？"}
    J -->|有| R
    J -->|没有或任务已完成| ANSWER
    D --> Q["输出检查与分层复核<br/>详见图 7"]
    L --> Q
    LIMIT --> Q
    ASK --> Q
    ANSWER --> Q
    Q --> P["持久化并向原渠道交付<br/>答案、公开来源、合法下载入口"]
    P --> F["结算、审计、任务摘要与记忆治理<br/>详见图 9"]
```

这是三条路径：确定性控制请求不必调用模型；简单问答通常一次主模型请求；资料或行动任务在同一个 Agent 内循环。不存在所有问题固定经过“规划模型→执行模型→审查模型”的要求。

## 2. 新消息如何续接、修改和取消任务

```mermaid
flowchart TD
    I["新消息＋可信会话身份"] --> L["读取当前任务与动作账本<br/>保留原请求、约束、执行记录"]
    L --> K{"新消息与任务的关系？"}
    K -->|不明确且影响操作对象| CL["澄清针对哪项任务<br/>不猜测要取消或修改的动作"]
    K -->|新任务| N["创建 taskId 与请求版本<br/>绑定代表、访客及会话"]
    K -->|继续或补充| C["合并已确认参数<br/>恢复缺口、证据引用和累计预算"]
    K -->|修改| D{"是否改变具体动作或关键参数？"}
    D -->|只改变答复排版| P["更新呈现版本<br/>不重复执行原动作"]
    D -->|改变金额、对象、收件人等| V["生成新动作摘要<br/>旧审批不能直接覆盖新动作"]
    V --> G["按当前权限与配置重新评估<br/>需要时取得新的有效审批"]
    N --> R["进入本轮路径选择"]
    C --> R
    P --> R
    G --> R
    K -->|查询状态| ST["根据服务端动作记录回答<br/>不让模型猜测完成状态"]
    K -->|取消| F["原子标记取消请求<br/>阻止新步骤和竞争中的派发"]
    F --> Z{"动作是否已提交？"}
    Z -->|尚未提交| CN["取消排队或待审批动作<br/>释放未使用预留"]
    Z -->|已经提交| CC{"是否有获准的取消或状态查询能力？"}
    CC -->|有| GW["通过统一执行检查取消或查状态"]
    GW --> CR["依据真实结果记录<br/>已取消、无法撤销或结果未知"]
    CC -->|无| UK["停止后续步骤<br/>保留已提交动作的实际或未知状态"]
    CN --> OUT["返回明确的任务状态"]
    CR --> OUT
    UK --> OUT
    ST --> OUT
```

任务版本不替代动作绑定。表示同意的一句话也不等于有效审批，审批主体必须由服务端认证。发生关键参数变化后，仍以配置中的 allow/ask/deny 和授权范围决定处理，不增加隐藏的强制审批。

## 3. 路径选择与每轮上下文组装

```mermaid
flowchart TD
    I["当前请求＋有效任务状态"] --> P["加载精简可信配置<br/>身份、回答范围、知识依据策略、权限"]
    P --> R["现有任务状态与明确规则先分流<br/>语义不明由主 Agent 在首次推理中选择"]
    R --> D["直接回答<br/>问候、翻译、改写、一般解释"]
    R --> K["代表资料<br/>所有者事实、政策、服务或指定材料"]
    R --> W["公共查询<br/>动态信息或公开历史资料"]
    R --> F["附件与文件<br/>读取、计算、整理或交付"]
    R --> A["业务动作<br/>已接入的预约、提交、取消或转人工"]
    R --> MIX["混合任务<br/>建立有依赖的步骤，共享一个主循环"]
    MIX --> K
    MIX --> W
    MIX --> F
    MIX --> A
    D --> NEED["确定本轮缺口<br/>不为满足流程而检索或执行"]
    K --> NEED
    W --> NEED
    F --> NEED
    A --> NEED
    NEED --> C["检查已有证据是否适用<br/>当前权限、来源版本和时效仍有效"]
    C --> LOAD["只加载必要内容<br/>相关历史、任务摘要、获准证据或附件元数据"]
    LOAD --> SK{"是否需要特定方法？"}
    SK -->|需要| SD["发现相关 Skill 简介<br/>按需加载获准版本"]
    SK -->|不需要| TS["从已授权工具目录选择相关能力"]
    SD --> TS
    TS --> DISC["保留发现其他获准工具的入口<br/>不把初次选择当成永久工具禁用"]
    DISC --> PACK["组装模型请求<br/>稳定规则＋代表配置＋最小运行状态<br/>当前问题＋必要资料＋本轮工具定义"]
    PACK --> M["同一个主 Agent 推理"]
    M -->|回答| OUT["候选答案进入输出检查"]
    M -->|检索、加载 Skill、读文件或执行| GW["统一工具执行检查"]
    GW --> OBS["回填数据或结果<br/>再按新缺口调整本轮上下文"]
    OBS --> NEED
```

这些路径按任务需要组织，不是“股票/天气/地理”等关键词硬路由，也不固定 Web、MCP、浏览器的优先级。优先选择符合权限、对象、时效和输出要求的能力，在同等有效的方法中比较可靠性、成本与延迟。

上下文分为五层：稳定系统规则；已发布的代表身份/范围/性格；服务端最小运行状态；用户原请求；经过授权的证据、记忆、Skill 和工具结果。最后一层不提升为权限或系统指令。历史裁剪必须保留工具调用/返回配对、未决事项与关键动作状态。

当前未配置的独立 Web 搜索后端不注册给模型。公网浏览器可访问网页及搜索结果页，接入真实搜索服务后再扩展目录。

## 4. 知识与记忆：先授权、再取正文，支持有效证据复用

```mermaid
flowchart TD
    Q["需要某项资料或相关记忆"] --> S["由服务端绑定检索范围<br/>代表、访客、会话、渠道和授权版本"]
    S --> TYPE{"数据源是否允许进入普通问答？"}
    TYPE -->|凭证类或禁止的数据源| DENY["禁止读取正文<br/>不泄露隐藏标题或存在性"]
    TYPE -->|允许的数据类别| AUTH["检查来源可见性、归属、撤回和同意状态"]
    AUTH -->|身份不足| ID["验证身份或权限元信息<br/>不先加载敏感正文"]
    AUTH -->|存在可见范围| CACHE{"是否有仍适用的证据缓存？"}
    CACHE -->|有且重验有效| REUSE["复用证据引用与必要内容<br/>不把历史助手回答当成证据"]
    CACHE -->|没有、过期或版本变化| SEARCH["仅在可见范围内召回<br/>关键词＋语义检索"]
    SEARCH --> RR["重排并取必要上下文<br/>保留条件、例外、单位与生效时间"]
    RR --> STATUS{"检索结果状态"}
    STATUS -->|ok| EV["形成结构化证据包<br/>正文、适用范围、版本、时间、公开引用"]
    STATUS -->|no_match| GAP["说明未取得支持证据<br/>允许一次有目的的查询调整"]
    STATUS -->|unavailable| ERR["记录服务不可用<br/>不能把故障当成资料不存在"]
    STATUS -->|conflict| CON["保留冲突与各自条件<br/>不能拼接为确定结论"]
    REUSE --> CHECK["注入前再确认当前可见性"]
    EV --> CHECK
    CON --> CHECK
    CHECK -->|有效| MODEL["作为资料提供给主 Agent<br/>不能改写规则与权限"]
    CHECK -->|失效| DENY
    ID --> RET["返回安全的状态或下一步"]
    DENY --> RET
    GAP --> RET
    ERR --> RET
```

知识库绑定、联系人记忆和代表经验采用不同范围。跨渠道联系人记忆需要同一可信身份及有效同意；匿名访客保持渠道隔离。普通知识检索、缓存、发布快照 fallback 都不能绕过上述过滤。

## 5. 工具执行检查与审批恢复

```mermaid
flowchart TD
    CALL["主 Agent 提出工具和参数<br/>提议不是执行许可"] --> CAT["读取主机验证的能力契约<br/>行为分类、输入输出、授权、审批、恢复能力"]
    CAT --> KNOWN{"工具存在且行为已明确分类？"}
    KNOWN -->|否| BLOCK["不执行<br/>返回能力缺失或分类未知"]
    KNOWN -->|是| IN["校验参数、目标与数据发送范围<br/>身份由服务端绑定"]
    IN --> PARAM{"关键参数完整且有效？"}
    PARAM -->|否| ASK["返回需补充的参数<br/>不派发动作"]
    PARAM -->|是| AUTH["重新校验当前对象级权限<br/>数据可见性、动作许可和业务前置条件"]
    AUTH -->|不允许| BLOCK
    AUTH -->|允许| BUD["检查剩余额度、执行预算与资源限制"]
    BUD -->|不足| LIMIT["不执行并说明限制"]
    BUD -->|可用| ACT["建立或查找稳定动作记录<br/>actionId＋规范化参数＋幂等标识"]
    ACT --> OLD{"同一逻辑动作是否已有结果？"}
    OLD -->|已确认完成| RECEIPT["返回原结果<br/>不重复执行"]
    OLD -->|已提交且结果未知| REC["进入恢复流程<br/>见图 6"]
    OLD -->|尚未提交| POLICY{"当前审批策略"}
    POLICY -->|deny| BLOCK
    POLICY -->|allow| READY["执行前最终重验<br/>取消、权限、预算、业务条件"]
    POLICY -->|ask| MATCH{"是否存在有效匹配审批？"}
    MATCH -->|有| READY
    MATCH -->|无| SAVE["保存 checkpoint 和待审批动作<br/>参数、目标、授权范围、效力与截止时间"]
    SAVE --> WAIT["等待规定主体审批<br/>暂停 Agent，不启动待批准动作"]
    WAIT -->|拒绝、过期或取消| CLOSE["终止相应待执行动作<br/>释放不再需要的预留"]
    WAIT -->|批准| VERIFY["认证审批者并重新比较动作绑定<br/>检查有效期、使用次数、权限与状态变化"]
    VERIFY -->|不匹配或失效| CLOSE
    VERIFY -->|通过| READY
    READY -->|条件已变化| BLOCK
    READY -->|通过| TX["原子取得派发资格<br/>消费适用审批、预留预算、记录 Outbox"]
    TX --> EXEC["进入执行与结果恢复<br/>见图 6"]
```

只读、访问授权、需要审批和幂等是独立属性。旧审批不能因为任务 ID 相同就复用，也不能因为任务文字变动就一律失效；由服务端比较真实动作。仅改变回复排版不改变原动作，收件人、金额、对象等关键变化不得套用原审批。

服务端数据库事务只保证本地派发约束；外部恰好一次效果仍取决于提供方的幂等、状态查询和条件提交能力。

## 6. 执行、故障与结果未知恢复

```mermaid
flowchart TD
    IN["已获派发资格的动作"] --> P["持久化发送意图<br/>动作 ID、原请求、幂等键、累计预算"]
    P --> KIND{"获准能力类型"}
    KIND -->|知识、记忆或 Skill| DATA["受控资料接口<br/>执行当前可见性检查"]
    KIND -->|公共网页| WEB["已配置的 Web 或 All-in-One 浏览器<br/>网页内容始终作为数据"]
    KIND -->|代码或文件| CODE["检查代码来源与实际运行边界<br/>文件、网络、凭证、资源、产物限制"]
    KIND -->|业务 MCP 或转人工| BIZ["调用已发布匹配接口<br/>携带原幂等键和适用业务条件"]
    CODE --> SAFE{"所需边界实际可落实？"}
    SAFE -->|否| NO["不执行该脚本<br/>标签或审批不能替代隔离"]
    SAFE -->|是| RUN["在受限会话中执行"]
    DATA --> RES["接收并规范化实际结果"]
    WEB --> RES
    BIZ --> RES
    RUN --> RES
    RES --> STATE{"执行结果"}
    STATE -->|已确认成功| OK["保存业务回执、证据或产物"]
    STATE -->|部分成功| PART["按子动作记录已完成与未完成<br/>不整批重放"]
    STATE -->|明确失败| FAIL["保留失败原因<br/>只有确认安全且预算允许时才重试"]
    STATE -->|超时或可能已提交| UNKNOWN["记录 unknown<br/>冻结该逻辑动作的重复提交"]
    UNKNOWN --> QUERY{"有获准的状态查询能力？"}
    QUERY -->|有| QS["经同一权限和预算检查查状态"]
    QS -->|取得权威状态| RESOLVED["保存权威确认状态"]
    QS -->|仍未确定| IDEM{"提供方具备可靠幂等恢复？"}
    QUERY -->|无| IDEM
    IDEM -->|有且预算允许| RETRY["重验授权后用原请求和原幂等键恢复"]
    RETRY --> RES
    IDEM -->|没有或预算不足| MANUAL["保留未知并停止自动提交<br/>等待核查，不换工具重做"]
    NO --> OBS["回填结构化观察结果给主 Agent"]
    OK --> OBS
    PART --> OBS
    FAIL --> OBS
    RESOLVED --> OBS
    MANUAL --> OBS
```

当前 All-in-One 为公网模式，不能标成实例级禁网。浏览器 GET 也不能仅凭方法名就认定无副作用。执行成功只是本次工具/动作结果，是否完成用户全部目标还要进入图 7。

## 7. 主 Agent 停止条件、复核与交付

```mermaid
flowchart TD
    I["候选答案＋原请求＋约束<br/>证据、动作状态及产物清单"] --> HARD["服务端硬检查<br/>权限与撤回、动作状态、引用、产物、任务版本"]
    HARD --> H{"硬检查结果"}
    H -->|不允许披露或宣称成功| SAFE["去除不允许内容或返回明确限制<br/>模型不得覆盖此决定"]
    H -->|缺少可补齐的证据| GAP["列出具体缺口"]
    H -->|通过| RISK{"是否需要独立语义复核？"}
    RISK -->|简单、低风险且无未决问题| STYLE["按代表风格组织答案<br/>不额外调用审查模型"]
    RISK -->|复杂、冲突、承诺或失败恢复| REVIEW["只读语义复核<br/>检查相关性、事实依据、完整性和表达"]
    REVIEW --> V{"复核结果"}
    V -->|通过| STYLE
    V -->|仅需表达修订| FIX["有限次修订<br/>不新增事实或执行动作"]
    FIX --> HARD
    V -->|需要更多证据| GAP
    V -->|必须人工核查| HUMAN["记录需核查原因<br/>有获准渠道才发起真实交接"]
    GAP --> B{"仍有获准方法且预算允许？"}
    B -->|有| LOOP["回到主 Agent 补具体缺口<br/>保留已完成动作，累计预算不重置"]
    B -->|没有| PART["说明已知结果、剩余缺口和限制"]
    STYLE --> MODE{"展示方式"}
    MODE -->|可流式的低风险输出| STREAM["轻量检查后逐段展示"]
    MODE -->|需完整放行检查的输出| BUFFER["先缓冲，检查通过后展示"]
    SAFE --> SAVE["持久化语义状态与可交付内容"]
    PART --> SAVE
    HUMAN --> SAVE
    STREAM --> SAVE
    BUFFER --> SAVE
    SAVE --> SEND["通过渠道 Outbox 交付<br/>公开来源、数据时间、合法文件入口"]
    SEND --> ACK{"交付是否获得确认？"}
    ACK -->|是| DONE["按既有账本规则结算<br/>完成本轮交付记录"]
    ACK -->|否或未知| DELIVERY["按渠道幂等机制恢复交付<br/>不重新执行业务动作"]
```

风险来自服务端能力、数据类型和实际动作，不能由模型一句“低风险”免检。简单问题不需要独立语义复核，但不绕过范围、权限与输出约束。需要放行前检查的正文必须先缓冲，不能依赖事后撤回已经展示的内容。

排队、业务执行、任务语义完成和消息送达分别记录：消息发送成功不等于用户任务完成，任务 partial 也不等于整个系统发生故障。

## 8. 附件和文件交付子流程

```mermaid
flowchart TD
    U["附件分析、计算或文件请求"] --> OWN["检查附件归属、类型、大小与可读范围"]
    OWN --> NEED{"用户需要读取、计算还是交付文件？"}
    NEED -->|仅读取或计算| READ["通过获准能力读取实际内容<br/>文件名不是内容证据"]
    NEED -->|交付文件| CAP["查共享产物能力清单<br/>支持格式、数量、大小和验证器"]
    CAP --> SUP{"格式与数量当前受支持？"}
    SUP -->|否| ALT["说明限制并给可行替代<br/>不把替代格式冒充原交付完成"]
    SUP -->|是| READ
    READ --> SCRIPT{"输入是否包含待执行脚本？"}
    SCRIPT -->|是| INSPECT["只读检查脚本及副作用<br/>所需限制不能落实则不自动运行"]
    SCRIPT -->|否| METHOD["按需发现并加载相关 Skill"]
    INSPECT --> CHECK{"检查通过且所需限制可落实？"}
    CHECK -->|否| ALT
    CHECK -->|是| METHOD
    METHOD --> GW["经统一工具执行检查运行<br/>图 5、6"]
    GW --> RESULT{"任务输出"}
    RESULT -->|只需答案| EVID["形成实际读取或计算证据<br/>回主 Agent 组织答案"]
    RESULT -->|需要文件| FILE["取得真实产物<br/>当前仅开放已验证格式"]
    FILE --> VALID["验证存在、大小、真实格式与可解析性<br/>检查内容是否满足请求"]
    VALID -->|失败| FAIL["报告未交付或有界修复<br/>不伪造链接、扩展名或成功信息"]
    VALID -->|通过| ART["保存 Artifact 与校验值<br/>生成受权限控制的下载引用"]
    ART --> ANSWER["交付答案与合法产物入口<br/>日志与文件分开"]
    FUTURE["第三阶段扩展<br/>真实二进制与多文件协议"] -.-> FILE
```

第一阶段收紧为当前经验证的单个文本/CSV/JSON；浏览器截图是另一项已存在的产物能力。PDF、XLSX及其他二进制、多文件能力在真实字节传输、解析验证与下载链路通过后才注册，不预先承诺。

## 9. 持久化、审计、记忆和评测反馈

```mermaid
flowchart TD
    EVENTS["各阶段的结构化事件"] --> DB["数据库作为状态与授权事实源<br/>任务、动作、审批、证据使用和额度账本"]
    DB --> AUDIT["受限审计与故障追踪<br/>记录版本、调用、状态、时间和费用"]
    AUDIT --> PRIV["最小化与脱敏<br/>不记录凭证或完整隐藏推理"]
    DB --> TASK["更新短期任务摘要<br/>约束、未决事项、证据引用和动作状态"]
    TASK --> NEXT["下一轮先恢复真实状态<br/>再决定是否读取更多资料"]
    DB --> MEMORY{"是否存在获准的长期记忆候选？"}
    MEMORY -->|无| SKIP["不写长期记忆"]
    MEMORY -->|有| GOVERN["自动治理<br/>来源、范围、同意、最小化、有效期与敏感性"]
    GOVERN -->|不合格或不确定| QUAR["阻断或隔离<br/>不进入可召回记忆"]
    GOVERN -->|合格| STORE["保存结构化且范围明确的记忆版本"]
    STORE --> INDEX["更新可重建检索索引<br/>撤回后立即禁止召回"]
    PRIV --> EVAL["形成失败样例与对照评测<br/>正确性、答案质量、无关调用、重复动作、延迟"]
    EVAL --> CHANGE["提出配置、提示词或接口改进"]
    CHANGE --> RELEASE["经授权发布与回归测试生效<br/>不从一次对话自动修改所有者政策"]
    RELEASE --> NEXT
```

联系人偏好与代表经验遵守现有自动记忆治理；不会新增日常记忆人工审批。访客自述可以记录为未验证偏好或信息，但不能成为身份或访问授权。临时行情、模型猜测和失败结果不能自动变成长期事实。

## 10. 服务落点及当前差异

| 层 | 服务或模块 | 复用 / 改造 |
| --- | --- | --- |
| 渠道入口与交付 | reps/web、Matrix/Telegram 适配器、Outbox | 复用可信入口、去重和交付；完善语义状态展示 |
| 任务与主循环 | conversation-worker、model-runtime/Pi | 复用单循环及恢复；补任务修订、候选路径与上下文选择 |
| 代表行为配置 | domain、representative-setup | 新增独立身份/回答范围/依据策略；行动权限复用 grants |
| 资料层 | web-data、MemoryUseRun、知识与记忆检索 | 强化正文前 ACL、证据条件、缓存复用和撤回检查 |
| 能力与执行 | capability-policy、compute-protocol、compute-broker | 统一分类、作用范围、审批绑定和端到端幂等 |
| 沙盒 | Tencent All-in-One | 复用真实浏览与代码环境；如实描述公网边界 |
| 输出 | 服务端 output gate、可选语义复核、Artifact | 硬检查常驻；语义复核按需；分期扩展文件格式 |
| 观测与优化 | 审计、账本、回归/eval | 区分真实完成、失败、未知、跳过与成本，不只统计工具调用 |

主要待新增/完善：统一任务分流；相关能力选择与发现；简单问答快速路径；证据复用；分层核验；独立业务范围配置；完整二进制/多文件协议。图中的目标机制不得理解为已经全部上线。

### 模型调用预期

| 场景 | 目标路径 | 是否固定加规划/复核模型 |
| --- | --- | --- |
| 状态查询、明确取消 | 服务端直接处理与回答 | 否；通常 0 次模型 |
| 问候、翻译、允许范围的一般解释 | 主模型直接回答＋必要硬检查 | 否；通常 1 次模型 |
| 指定知识问题 | 取得获准证据后回答；可复用有效证据 | 不固定；可在主循环中选择检索 |
| 公共查询 | 主模型选择相关工具，取得结果后回答 | 不固定；工具选择与回答通常需要多个轮次 |
| 附件、业务、多步骤 | 同一主 Agent 完成有依赖的步骤 | 仅复杂或高风险时增加语义复核 |

以上是目标路径，不是保证的固定调用次数。授权检查、来源查询和模型推理是不同操作，不应在指标中混为一谈。
