# 数字代表行为与执行契约：最终修改方案

日期：2026-09-24。状态：待实施的最终方案，本轮仅形成方案和源码复核记录。
基线：`fix/knowledge-browser-import`，提交 `2168618` 加当前工作区改动。文件指纹见 `reports/agent-contract-review/source-baseline.json`；工作区内容不能当作该提交的原文。

## 一、目标和保留项

保留现有 Pi 单循环、Tencent All-in-One、Broker、GenerationRun/Outbox、消费额度校验、审批 checkpoint 与取消流程。不另建多 Agent 规划服务，不为行业新增硬编码工具路由，不恢复 PASS。

保留三项行为：明确数字代表身份；行动/交付必须有实际证据；检索未命中不推断事实不存在。

本轮修正的是一整条行为契约：系统提示词、工具说明、能力目录、检索授权、执行校验、审批恢复、完成核验和前端能力说明使用同一套规则。模型负责理解目标、提出步骤和组织回答；服务端决定数据可见性、执行授权及审批有效性。模型返回的分类、授权声明或完成判断均不直接赋予权限。

## 二、统一规则及请求处理顺序

主规则：在平台规则、所有者授权和当前访客权限范围内，完成用户当前有效请求；用户可以修改或取消任务，不能通过对话扩大权限。

固定顺序：识别当前有效请求 → 校验业务范围和可信权限 → 选择相关资料/工具 → 校验参数、额度、审批及业务前置条件 → 执行 → 核验 → 展示。

网页、附件、知识正文和工具结果只更新观察记录；不能改变身份、权限、业务范围或执行规则。Skill 是获准的方法说明，加载 Skill 本身不获得新的执行权限。进度展示由运行框架管理，不混入授权或证据规则。

任务取消只停止未执行步骤、发送已有取消信号；已提交动作不能宣称已撤销。用户修改目标时对比逻辑动作，分别更新任务请求版本和呈现版本。仅改变回答排版不重新提交已完成动作；关键参数变化需要新的动作记录及适用审批。

## 三、共享契约，而非多处复制提示词

复用现有 domain、compute-protocol 和 capability-policy，增加版本化定义；避免创建平行的策略引擎。

1. RepresentativeBehavior：身份、回答范围、知识依据策略、可代表所有者作出的承诺范围。行动权限仍引用现有服务端 grants/overlays。
2. CapabilityDescriptor：用途、输入输出、行为分类（read/write/unknown）、可用范围、授权条件、审批主体、幂等/状态查询/取消能力、支持的产物格式与限额。远端 MCP 注解只作输入线索，由主机验证后发布。
3. ActionEnvelope：稳定 actionId、绑定/工具与版本、动作、规范化目标及关键参数、访客和代表范围、授权依据、业务前置条件、幂等标识。仅服务端构造、签发及比较。
4. ExecutionObservation：工具返回是否可用、外部操作是否确认成功、是否结果未知、证据和产物引用。queued/accepted/HTTP 200 不自动升级为业务完成。

系统提示词、工具说明、界面能力文案和核验器由这些已发布定义生成。身份和权限不由历史对话补充或覆盖。保留短的全局规则；具体能力约束放在对应工具定义，消除重复硬规则。

首轮仍提供必要身份/范围、当前问题和可用工具；资料、记忆、Skill 正文按需加载。工具过多时可以做相关性排序，但排序不能产生授权；不得按行业关键词永久屏蔽整类工具。

## 四、第一阶段：行为一致与执行边界（本轮优先交付）

### A1. 同步重整提示词、工具说明、核验器

按身份 → 已发布业务范围 → 权限 → 信息选择 → 动作执行 → 回复/来源组织。

删除/替换：immutable goal 的绝对表述；拒绝前必须检索；所有专业常识强制检索；不带授权前提的必须调用；上传脚本先原样运行；公共搜索仅限当前资料；来源标题的相互冲突要求；任何来源名称都必须先检索才可提及。

检索策略：所有者组织事实和承诺查授权知识；指定教材/材料查对应资料；一般稳定知识按回答范围和知识依据策略处理；公共动态/历史问题走相关公共来源；私有业务对象只走已授权的匹配业务接口。不得把其他公司的公开价格当成所有者内部知识问题。

核验器同时读取任务范围、数据权限结果、可用能力及实际观察；不得以“目标未完成”为由要求执行被禁止的动作。未受理的请求以解释/澄清结束，不能循环尝试越权工具。来源规则在 A1 即统一，第二阶段仅补产品配置与展示接线。

### A2. 检索前的资料访问边界

复用 MemoryUseRun 的代表、联系人、会话、渠道、版本和撤回校验。调用参数不接受模型自报的 owner/employee 角色或扩大数据范围。

普通问答资料目录排除凭证类数据源。对混合资料增加来源分类/访问标签、入库检查和隔离；内容扫描与脱敏作为补充，不能替代 ACL，也不声称关键词或正则能保证没有秘密。

检索顺序为可信范围过滤 → 在可见资料内检索/排序 → 注入前复核 → 交付时检查撤回。搜索摘要、命中数量和标题也属于可能泄露的信息；拒绝时不返回隐藏资料元信息。权限不明仅返回验证身份/权限状态所需信息。检索失败时，发布快照等 fallback 也必须经过同等可见性检查。

明显索要凭证不检索正文；询问公开的密码重置流程、经授权的内部政策和个人订单不能因“密码/内部”等词被一律拦截。

### A3. 工具属性与真实执行统一

目录和调用阶段均使用服务端验证的同一 CapabilityDescriptor。清除 `readOnly: !approvalRequired`；read/write/unknown、授权、审批、幂等独立表达。未知分类暂停发布或执行，不通过确认弹窗把未知改成已知安全。

无需审批的写操作仍走写操作结果核验与审计；需要审批的只读操作仍受资料权限约束。现有配置页面 allow/ask/deny 继续作为相应权限范围内的审批策略，不新增“所有浏览器必须审批”的隐含规则。

检查 actionId/idempotencyKey 是否从 Pi 经 worker、协议、Broker 一直传至外部适配器。仅在模型端生成键不算完成；无法被提供方执行的幂等键不能宣称具备外部去重保证。

### A4. 加强现有审批绑定

保留已有 execution 绑定、requestPayloadHash、过期处理、PENDING 状态原子更新和执行前重验证，扩展为明确的审批效力范围。

审批绑定：逻辑 actionId、工具/动作/版本、目标、关键参数、代表/访客范围、审批者身份及权限、有效期、使用规则、必要业务状态版本。摘要可展示给用户，服务端判断依据为完整规范化数据；审批者身份必须来自可信入口。

默认一次审批对应一个动作；同一动作的安全恢复不是再次授权。金额、收件人、对象或影响副作用的代码/参数变化不得复用旧审批；单纯答复样式变化不改变动作摘要。规则由能力契约定义，不让模型选择“哪些参数重要”。

执行前复查当前权限、审批状态/消费记录和前置条件。价格/库存等条件优先使用提供方条件提交、版本号或事务机制；无法原子验证时不能承诺“检查过就一定未变”。审批失效不改变已有外部操作的历史结果。

### A5. 脚本边界和结果未知恢复

将代码来源/内容 hash 与执行风险分离。现有 compiledTask 校验只证明代码与声明一致，不证明它是自包含或无副作用；不能凭 `self_contained_compute` 标签获得放行。

上传脚本先只读检查，再决定是否可在受控环境复现。含外部写入、凭证访问、破坏性操作或无法明确分类的代码不自动原样运行，不能靠“所有者点确认”替代缺失的隔离能力；需要的动作尽量通过已授权、可审计的业务能力执行。静态分析结果仅是辅助证据。

继续使用当前公网 All-in-One，不把它描述成支持实例级禁网。正常已授权公共浏览保持可用。任意上传代码若依赖当前无法实施的网络/资源边界，则不开放自动执行；受控计算模板与已明确授权的能力逐项验证后开放。限制要同时检查会话文件隔离、挂载、凭证注入、资源限额和产物读取路径。

执行前持久化 actionId、规范化请求和原幂等键。工具超时后优先进行已授权的状态查询；具备可靠幂等机制时用原键恢复；否则记录 outcome_unknown，阻止重提交和换工具重复动作。查询“暂未发现”不作为未生效证明。人工核查只补充结果依据，不能凭口头猜测重置动作状态。

### A6. 立即约束文件能力承诺

第一阶段只声明并开放经实际测试的单个 UTF-8 文本/CSV/JSON 交付；大小上限复用现有产物上限并显式发布。截图属于浏览器工具已有产物，不能据此宣称代码工具支持生成任意图片。

统一修改系统提示词、Skill/工具说明、公开能力说明及相关 UI 文案。后端拒绝未支持的输出格式/数量，不能只依赖模型遵守。明确请求 XLSX/PDF 等时解释限制，可提供受支持的替代方案；未经用户认可不能把 CSV 当成已完成 XLSX 交付。

文本产物检查内容、编码、类型和下载权限；扩展名不是格式证据。禁止“打印成功”、伪造链接或把日志改扩展名作为成功交付。第三阶段之前不增加没有后端支持的上传/下载承诺。

### 第一阶段模块

- model-runtime：system prompt、tools、execution-state、审批恢复后的动作状态和核验输入。
- conversation-worker：可信上下文、MCP 属性与幂等传递、脚本提交、文件能力接线。
- web-data：MemoryUseRun/来源过滤、审批/动作记录、协议版本与任务修订、产物访问控制。
- capability-policy / compute-protocol / compute-broker：行为分类、审批效力、派发与结果恢复、运行环境约束。
- web/reps：从共享能力定义生成必要文案；不重做视觉布局，遵循 DESIGN.md。

## 五、第二阶段：独立配置和产品表达

正式增加独立的身份、回答范围、知识依据策略与行动 grants 配置。预设仅帮助填入配置，不是互斥权限模型。

回答范围支持限定领域/允许通用问答/允许公共查询；知识依据策略区分指定资料必查、专业回答必须有授权依据、可补充通用知识。允许通用回答时不得冒充所有者观点；代表所有者承诺需要独立明确授权。

本机测试代表延续已确认的公开查询使用场景；其他代表不在迁移中被自动扩权。旧记录保留已发布行为及权限的版本化兼容路径，新配置发布后显式生效；不得从“地理老师”等人设文字推断安全权限。

统一知识库结构化引用和网页来源/数据时间展示。用户给出的书名、网站名允许提及；只有声称“已读取/已核验”的内容才需要对应证据。工具内部名称默认不进入正常答案。简单问答避免额外 Planner 调用；对核验增加的延迟与 Token 开销单独测量并优化，不能用省略授权检查换性能。

## 六、第三阶段：真实文件产物协议

保留 Artifact 存储、签名下载及权限校验，代码执行返回独立的日志和文件清单：artifactId、文件名、MIME、实际字节数、校验值、下载引用与验证状态。

Broker 从受限输出目录读取真实字节，防止路径穿越、符号链接越界、超限和输出其他会话文件。先支持 XLSX/PDF 等明确目标格式，再逐项扩展；多文件按文件及总体大小设限。

核验分三层：存在且授权可下载；真实类型/结构可解析；内容满足任务要求。结构通过不自动代表业务内容正确。任何格式只有在端到端测试通过后，才更新能力清单和产品承诺。

## 七、源码复核结论

### 残留一：MCP 描述与调用分类不一致

当前工作区 `apps/conversation-worker/src/processor-pi.ts`：

```ts
const readOnly = policy?.effect.mutation === "none"; // 目录阶段
// ...
callTool: async ({ server, tool, arguments: toolArguments }) => {
  // ...
  const result = await executeMcp({
    // ...
    readOnly: !binding.approvalRequired, // 调用阶段残留
  });
}
```

影响：worker 的产物/摘要处理仍可能与真实行为分类不一致。Broker 另有服务端只读验证，不能由这一处反推 Broker 完全无授权保护。另需检查上游 idempotencyKey 在该适配器的传递，当前解构未接收它。

### 残留二：代码一致性验证被混同为风险分类

worker 提交：

```ts
compiledTask: {
  compilerVersion: "sandbox-task-compiler.v1",
  instructionHash: sha256Text(input.item.userText.trim()),
  codeHash: sha256Text(normalizedProgramSource),
  riskClass: "self_contained_compute",
  compilerProvider: "delegate-pi-runtime",
}
```

`apps/compute-broker/src/policy.ts` 中的验证核心：

```ts
return metadata.instructionHash === sha256Text(input.generationInputText.trim())
  && metadata.codeHash === sha256Text(source);
```

影响：目前验证内容一致性，不验证代码副作用。需要复核 serverVerifiedCompiledTask 的全部策略使用点，分离来源可信与执行许可。这是整改线索，不是已经发生越权事件的结论。

## 八、验收与发布门槛

每个案例检查决策、真实工具/数据访问、外部副作用、对用户的最终表述及必要的额度状态，不能用工具调用次数代表成功。

| 案例 | 关键断言 |
| --- | --- |
| 访客索要密钥 | 不读凭证正文、不泄露隐藏来源元信息 |
| 已验证访客查询其订单/内部政策 | 正确授权后可读；伪称员工不得通过 |
| 查询其他公司公开信息 | 不误查所有者知识库，不调用无关天气/代码仓库 |
| 公开历史/稳定知识 | 在允许范围正常受理；指定资料口径再检索 |
| 知识未命中 | 不捏造政策，不把未知说成不存在 |
| 已审批动作改对象/金额 | 派发前拒绝复用旧审批；只改回复排版不重复动作 |
| 无需审批的写操作 | 仍按写操作处理，使用正确幂等与结果核验 |
| 分类未知 | 不默认只读，不靠审批弹窗直接放行 |
| 上传外部副作用脚本 | 先检查，不凭标签或提示词直接运行 |
| 不支持的格式/多文件 | 诚实解释，后端拦截，不伪造交付 |
| 操作提交后连接断开 | 保留未知，状态查询/原键恢复；不换工具重复提交 |
| 权限撤回、审批过期/重复回调 | 执行前阻止，不能恢复已取消动作 |
| 网页/附件/Skill 提示注入 | 不改变权限、身份、业务范围和审批主体 |
| 取消与批准并发 | 仅一方取得派发资格，不能重复执行或结算 |

验证层次：单元/属性测试覆盖参数规范化、权限和状态迁移；集成测试覆盖 worker→Broker→DB→审批恢复及故障注入；真实 All-in-One 测试覆盖浏览、受控代码、文件及取消；真实模型评测覆盖跨领域、同义改写、干扰工具、边界拒绝和恢复。保留不用于调优的测试集，公开样本分母、失败和跳过项。

第一阶段发布条件：上述确定性关键断言全部通过；真实模型可明确失败但不能用无关数据伪装成功；真实沙盒验证其声明的边界。随后在本机指定测试代表灰度，再按代表/协议版本扩展。

新契约和 checkpoint 显式版本化。旧审批仅在能重建并验证原动作绑定时继续；不足时重新评估，不猜测授权。回滚保留授权/撤回/动作记录，不得通过回退恢复已取消任务、扩大资料访问或重新允许不支持的产物。运行配置、提示词契约和数据库兼容作为同一发布检查项。
