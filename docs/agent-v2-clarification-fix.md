# V2 澄清与内部资料未命中修复

2026-10-19，基于 `codex/agent-architecture` 的 `5835e30` 继续开发。模型、工具选择和是否澄清仍由一个 PI 主模型决定；没有增加业务关键词路由、分类模型或固定核验/改写链。

后续按用户要求切换到 `qwen3.8-27b`，见[模型切换与重新验收](agent-v2-qwen38-validation.md)。下文保留原 `qwen-plus` 的结果，不用原模型的通过率代替新模型验证。

## 结果

最终配置做了 **3 轮独立真实模型复测**：每轮 12 个首次请求 + 3 次澄清恢复，共 45 个请求。三轮使用独立 request/session ID，运行时、提示词、工具定义和模型配置相同；轮间并发用于缩短验证时间，不作为性能基准。

| 检查组 | 数量 | 行为结果 |
| --- | ---: | --- |
| 缺少地点，包含简短问法、气温、降雨与催促直接查询 | 12 | 全部先询问城市/地区，1 次主模型、0 次外部工具 |
| 内部资料未命中，包含个人奖金问法、主动提供个人信息、英文问法 | 12 | 全部实际检索后说明限制；未索取员工号、部门、职级、电话或凭据，没有编造金额 |
| 用户已给城市、可信位置上下文、知识命中、纯翻译 | 12 | 全部通过；已有位置时没有机械重复提问 |
| 用户补充城市后的恢复 | 9 | 全部完成查询，累计任务预算保留 |

原始自动评分为 **44/45**。唯一判分失败的英文回答是 `returned no supporting documents`，旧评分器只接受 `no ... record`，实际回答符合限制说明要求。修正评分器、加入该原句的回归测试后，同一批原始结果复核为 **45/45**；**没有修改或覆盖任何模型回答/原始失败记录**。另做英文真实模型复测 **3/3** 通过。

这是对这些场景的有限验证，不表示所有开放问题都稳定正确，也不替代真实 RAG/MCP/Postgres 全栈验收。部分回答仍会建议向 HR 等正式渠道核实；人工复核确认没有要求向本代理提交无用个人信息，且没有给出未支持的奖金金额。

## 原因与修改

1. **时区被当成位置线索。** 原上下文只有 `Asia/Shanghai`，没有明确的位置缺失状态。现在单独传递 `authorizedUserLocation`，默认 `null`，并标明时区仅用于解释日期。用户明确给出的查询地点仍可直接使用。worker 没有新增 IP/GPS 定位或默认城市。
2. **缺证据被当成缺用户参数。** 提示词区分“补充后有现成可执行路径的必要参数”和“没有资料/能力”。自由文本 `query` 不代表任意个人字段都可用于查询；个人字段必须由具体工具定义或实际取得的适用规则证明必要。未命中后用 partial 说明本次查找和当前能力限制，不编造原因或索要资料。
3. **意图被当成已执行。** 在必要上下文中加入实际工具结果摘要：名称、执行状态和来源数量。空数组表示本次尚无工具结果，不得声称已查询或未命中。没有复制原始参数或工具正文，没有据此做业务路由。
4. **主模型能力配置不足。** 提示词修复已让两条原题在原非思考模式下连续五次通过，但个人化改写仍失败。现有客户端将模型统一标为 `reasoning: false`。V2 为实际验证过的 `qwen-plus`（Agicto/Bailian、OpenAI-compatible Chat）登记 PI 原生 Qwen 能力，启用每次最多 1024 thinking token，仍是同一次主模型请求。

Qwen 的 `enable_thinking` / `thinking_budget` 参数依据 [阿里云官方文档](https://help.aliyun.com/zh/model-studio/deep-thinking/)；PI 0.85.1 的 `thinkingFormat: qwen`、`thinkingTokenBudgetField`、`thinkingBudgets` 已核对安装包类型与编码器，并通过实际请求和 wire-contract 测试。没有猜测其他模型族的能力，也没有换模型来冒充原模型修复。

## 执行与预算边界

- 本批历史验收使用 `agicto / qwen-plus`，temperature=0。旧 Pi 入口的绑定和默认配置不变。
- `DELEGATE_V2_THINKING_TOKENS=1024` 为新 V2 默认上限；设为 `0` 可关闭。未验证的模型保留原绑定。
- 思考额度包含在 `DELEGATE_V2_OUTPUT_TOKENS`（默认 2048）中，不额外增加响应总上限。PI 保留回答空间；V2 在最后收尾阶段或输出额度不够时关闭思考，避免用尽收尾预算。
- 所有 token（含思考）继续计入任务预算；没有额外分类/核验请求。最终资料未命中通常为一次选择/检索 + 一次正常回答。
- 思考正文不输出、不写 trace、不存澄清 session。测试覆盖原生思考内容过滤；评估只记录是否出现 thinking block 的数量和实际 usage。
- 增加思考会增加耗时和输出 token。本批缺地点请求耗时中位数约 4.8 秒，内部未命中约 18.5–24.7 秒（分组不同）；三轮并发、有缓存影响，不能据此宣称性能提升。费用单价未配置，实际费用仍为 N/A。若配置 `COST_USD`，单价必须对应实际使用的思考模式，不能沿用不匹配的计价假设。

- `prompt.ts`：通用参数/能力缺口规则，禁止推测目标和无依据的信息收集。

- `provider.ts` / `config.ts` / `cli.ts`：已验证的 Qwen 原生能力与集中预算；CLI、worker 和评估使用同一 V2 绑定。
- `evaluation-cases.ts` / `evaluate.ts`：原题、改写、正例和每次恢复的真实模型评估；评分不进入 serving runtime。

## 复现

在独立 worktree 配好原模型环境后：

```sh
pnpm test:agent:v2
pnpm eval:agent:v2 --live --suite=clarification --repetitions=3
pnpm eval:agent:v2 --live --ids=clarify,internal-miss --repetitions=5
# 对照关闭原生思考的行为（不代表与最终配置同样稳定）：
DELEGATE_V2_THINKING_TOKENS=0 pnpm eval:agent:v2 --live --suite=clarification
```

这里使用真实模型、受控合成工具数据，不调用生产人事系统、真实天气或实际个人账户。生产入口、部署配置、审批恢复和专项语义审核边界均未更改。
