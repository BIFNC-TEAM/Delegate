# V2 已完成天气任务干扰“你好”的修复

后续另修复了 CSV 输出契约及确定性失败恢复，最新 worker 镜像与配置入口见 [CSV 输出修复](agent-v2-csv-output-fix.md)；本页的上下文修复保持生效。

2026-10-19，修复并更新本机 `3002` 的地理代表 `founder-representative-2`。主模型仍为 `qwen3.8-27b`。

## 实际原因

用户截图对应请求的当前输入确实是“你好”，上一轮深圳天气任务已经完成。本次 V2 又执行了 3 次天气工具调用、4 次主模型调用，随后交付了新的天气回答；输入消息、GenerationRun 与输出消息关联一致，因此不是前端贴错回复，也不是旧版本入口。

问题在上下文组装：为了遵守资料撤回和权限边界，历史读取只保留用户发言，不直接重放旧助手答案。但 V2 把这些旧发言作为连续 user 消息传给模型，缺少已回复/完成状态和明确的参考边界。模型把“今天天气如何”“深圳”重新当成待处理指令。之前独立场景和澄清恢复测试没有覆盖“任务完成后再打招呼”的连续对话。

在独立匿名会话中按“今天天气如何 → 深圳 → 你好”再次复现，第三条又回答天气。[原始故障及独立复现](../reports/agent-v2/current-turn-reproduction.json)均保留，未改写用户原聊天记录。

## 修改

- 只为 V2 读取同一会话、同一 episode、当前消息之前的历史请求状态；优先采用真实取消/失败状态，旧流程只标为已回复，不推测其答案质量。
- 将旧用户发言和对应状态封装成 `conversation_reference` 数据，不再作为一串新命令重放。
- 主模型收到明确的 `activeTask` 状态；没有等待澄清的任务时为 `null`。系统提示要求以当前最新消息为目标，只在明确续问、更新或有效补参时继续相关工作。
- 主模型仍自主理解问候、感谢、翻译、话题切换和省略式追问。没有“你好/天气”等服务端关键词路由，没有新增分类、核验或改写调用。
- 历史原文的授权、短期记忆关闭、episode 和删除边界继续生效；没有把旧助手事实、工具正文或思考内容重新注入模型。

## 验证

机制与边界检查：V2 专项 **85 项通过**（现在包含历史请求状态回归）；conversation-worker 全量 **160 项通过**；model-runtime、worker、web-data 类型检查通过。最后补充的取消/失败状态优先级也有对应回归测试。

真实模型、受控工具进行了三轮共 12 个输入：[模型上下文评估](../reports/agent-v2/current-turn-model-evaluation.json)。9 个问候/感谢/翻译输入全部一次模型、零工具；3 个“那北京呢？”均选择了查询能力。该 fixture 固定返回上海，后者只验证追问工具选择，不证明北京天气回答完整；有一条明确说明数据不足但仍声明 completed，原样保留，不计为天气任务成功。

随后在实际 `3002` 页面 API、主数据库、原知识库和原 MCP 上跑了两条独立连续对话，共 12 次请求：

| 场景 | 实测 |
| --- | --- |
| 天气缺城市 → 深圳 | 两次均先澄清，再查天气并保留任务预算 |
| 已完成天气后说“你好” | 两次均正常问候；各 1 次模型、0 次工具 |
| 之后说“谢谢” | 两次均正常回应；各 1 次模型、0 次工具 |
| 翻译含“深圳天气”的完整文本 | 两次均只翻译；各 1 次模型、0 次工具 |
| “那北京呢？” | 保留历史指代，正常查询北京天气 |
| 切换为地图三要素 | 检索并引用原知识库《地理_01_地球与地图》 |

[真实产品复测记录](../reports/agent-v2/current-turn-live-verification.json)通过 run ID 从权威数据库核验，均为 V2 与 `qwen3.8-27b`。两个并行临时 HTTP 日志文件曾因毫秒文件名相同而覆盖；已按各自独立捕获的 run ID 从数据库恢复全部 12 条记录，并将临时测试驱动改为 UUID 文件名。没有靠缺失记录推算通过率。

测试是有限样本，不代表所有开放式对话必然正确；并行运行含排队等待，不把本次耗时用作普遍性能结论。
