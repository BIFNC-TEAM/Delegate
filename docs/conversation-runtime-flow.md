# 会话运行流程

新请求通过共享 Conversation Platform 入库，再由 conversation-worker 的 `processor.ts` 认领租约。所有代表使用 V2；Web、Matrix、Telegram 共享执行入口，渠道适配只负责身份、消息和交付。

1. 检查人工接管、额度、发布版本与来源权限，处理明确的取消及记忆控制命令。
2. 固定执行版本。旧版已开始请求停止自动续跑；历史已完成消息继续按原交付栅栏投递。
3. `processor-v2.ts` 构建授权上下文、工具、当前时间与预算。
4. PI 原生循环驱动主模型选择澄清、工具或回答；服务端校验、执行并记录真实事件。
5. 回答释放前复核来源访问权限，持久化答案、来源、调用过程与最小澄清状态，再通过既有渠道投递。

详见 [V2 运行说明](agent-v2.md)和[切换与历史兼容](agent-v2-cleanup.md)。业务语义由主模型决定，不再使用旧分类、核验、改写流水线。
