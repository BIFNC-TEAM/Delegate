# 代表记忆自动化重构开发计划

状态：代码实施完成，回归验证中

日期：2026-08-06

取代：2026-08-03 的顶层“记忆系统 + 人工审核”方案

## 1. 已确认的产品决策

- Dashboard 不再提供顶层“记忆系统”导航、总览、条目、使用记录或审批控制台。
- Owner 唯一入口是“数字代表 -> 配置 -> Memory”，所有设置严格绑定当前代表。
- 记忆不再等待 Owner、Reviewer 或 Operator 审批。系统根据版本化自动策略完成提取、最小化、总结、激活、更新、忽略、隔离和删除；不确定或失败一律关闭召回。
- 取消的是人工记忆审批，不是安全治理。候选隔离、不可变版本、自动策略审计、使用账本、删除证明、投影任务和库存对账继续保留在服务端。
- 公开知识继续由知识库独立负责创建、编辑、授权、草稿、发布版本和撤回。记忆重构不得删除、复制或改变知识库工作流。
- 通用 Approvals 仍处理 Action、Compute、支付、权限和其他需要人工确认的业务动作。它不是记忆审批，必须保持不变。

## 2. 数据边界

### 联系人记忆

- 用于当前联系人和当前代表的持续服务，不要求去标识化。
- 只保存白名单类别中的结构化、最小化事实，例如偏好、目标、约束、沟通方式和用户明确要求记住的低风险背景。
- 姓名、用户名、邮箱、电话、平台账号、外部 ID 等身份字段继续由 Contact/Profile 管理，不复制进语义记忆正文。
- 原始聊天、Owner 私有备注、Compute/Tool 原始产物、凭据、支付金额、余额、退款、权益、授权结论和持久化提示注入不得成为记忆。
- 默认按代表、联系人和来源渠道隔离。只有渠道映射到同一已验证 `AudienceIdentity`，且联系人明确同意跨渠道共享时，才能扩大到联系人跨渠道范围；匿名或未验证身份始终按渠道隔离。

### 代表经验

- 只保存对当前代表普遍有用、已去标识化、不可逆推出个人的信息模式。
- 必须由多个合格联系人或会话的独立证据聚合达到策略阈值；单条消息、单个联系人或 Handoff 完成事件不能直接生成代表级经验。
- 经验不得跨代表共享，不得包含联系人特有事实、可逆标识、原始对话、凭据、交易或权限事实。

### 短期记忆

- 仅指当前会话或 episode 内的有界最近轮次和当前任务状态。
- 不写入 OpenViking，不进入长期记忆生命周期，不因刷新、Handoff 完成或会话结束自动升级为长期记忆。
- 关闭后，新回复不再加载短期上下文；已经持久化的普通会话消息仍按会话产品自身的保留规则处理。

## 3. 设置契约

“数字代表 -> 配置 -> Memory”拆为四组：

1. 基础策略
   - 自动提取并应用
   - 联系人记忆
   - 联系人记忆跨渠道共享（Owner 仅允许该能力；联系人仍需使用同一已验证身份单独明确授权）
   - 代表经验
   - 长期记忆
   - 短期记忆
2. 渠道能力
   - Web、Matrix、Telegram 分别展示召回支持、提取支持和当前策略是否启用
   - “支持”和“启用”必须分开；渠道可支持该能力但仍由代表策略决定是否启用，具体会话缺少首次披露、身份映射或删除边界时按消息 fail closed
3. 保留策略
   - 长期记忆保存期限
   - 到期后立即停止召回
   - 到期行为：归档或进入异步物理清理
4. 高级设置
   - PostgreSQL/OpenViking 同步状态、最后成功时间、积压与失败数
   - 同步策略：PostgreSQL 权威、OpenViking 为可重建投影、逐项幂等、版本 fence、失败重试和定期对账
   - Provider、服务端生成的 namespace/Agent ID/Target URI、阈值和诊断摘要只读；普通 Owner 不得编辑任意目标地址

依赖规则：关闭长期记忆必须同时关闭长期召回和新增长期提取；关闭联系人记忆或代表经验立即阻断相应类型召回。Web、Matrix 和 Telegram 均支持按代表独立开启召回与提取；Matrix/Telegram 仅限已验证的一对一纯文本会话，并且必须先在精确渠道绑定内完成版本化记忆披露。联系人跨渠道共享默认关闭；Owner 开启能力后，只有 Web、Matrix、Telegram 私聊映射到同一已验证 `AudienceIdentity`，且联系人接受当前版本披露并明确授权时才能生成和召回共享安全摘要。任一条件缺失、授权撤回、身份解绑或策略版本变化都必须 fail closed。

## 4. 权威架构与自动决策

PostgreSQL 保存业务真相，OpenViking 只保存可重建检索投影。远端结果必须再次通过 PostgreSQL allowlist、当前版本、范围、保留和安全检查，不能单凭 URI 或相似度获得召回权。

```text
允许的来源消息引用
  -> 确定性敏感内容/来源/作用域检查
  -> 受约束的结构化提取与最小化总结
  -> 内部候选隔离
  -> 版本化自动策略决定
       ACTIVATE | UPDATE | NO_CHANGE
       BLOCK | QUARANTINE | DELETE | RETRY
  -> PostgreSQL 记忆与不可变版本
  -> 逐项 OpenViking 投影（仅长期记忆）
  -> 搜索 -> PostgreSQL 范围/安全复核 -> 模型注入 -> 公开来源
```

每次自动决策至少记录：策略版本、提取器版本、输入来源哈希、输出哈希、类别、范围、原因码、置信度、证据计数、决定、目标版本和时间。审计记录不得复制原始对话或被阻止的敏感正文。

同一语义键的相同事实返回 `NO_CHANGE`；纠正或变化创建新版本，并在同一事务内阻断旧版本。明确删除请求、来源消息撤回、同意撤回、策略停用或到期先立即阻断召回，再排队物理清理。

## 5. 实施阶段

### R0：契约与兼容边界

- 更新设计、开发和测试契约，冻结“无顶层入口、无人审批、失败关闭”的目标。
- 建立旧人工审核写路径、顶层页面、路由、DTO、测试和样式的调用清单。
- 标记绝对不能删除的知识库、通用 Approvals、公开知识投影、使用账本、删除证明和对账链路。

退出条件：每项旧代码都有“保留、兼容、替换或删除”结论，且没有把通用审批误归为记忆审批。

### R1：兼容性数据模型与自动策略账本

- 先做 additive migration：补充自动策略决定、短期记忆、跨渠道开关/同意证据和所需索引；不在同一发布中删除历史审核表或枚举值。
- 提供旧人工批准记录到已激活记忆的只读兼容，不再要求新记录产生人工决定。
- 所有新激活和更新必须有可验证的自动策略决定；缺失、格式错误或版本未知时 fail closed。

退出条件：新旧已生效记忆都可安全读取，新写入不依赖人工审批，数据库回滚不会恢复不安全召回。

### R2：自动提取、总结、更新与删除

- 对允许的 audience 消息执行统一的来源、安全、类别和最小化检查。
- 联系人记忆使用稳定语义键去重；相同事实不增版本，变化创建新版本，冲突时采用保守更新或隔离。
- 代表经验先累计去标识化证据，达到多来源阈值后生成聚合版本；证据减少到阈值以下时立即阻断。
- Matrix provider edit/redaction、Telegram `edited_message`、联系人精确删除请求、策略关闭、保留到期和同意撤回触发统一失效/清理流程；Telegram 普通客户端删除不可观测，不得作为失效触发器。

退出条件：抽取、总结、无变化、纠正、撤回、到期和删除均有确定性测试，任何异常不会写入生产投影。

### R3：运行时范围与上下文

- 召回同时校验代表、联系人、渠道或已同意的跨渠道身份范围、当前有效版本、保留期、策略开关和有效投影。
- 短期上下文仅加载当前 conversation/episode 的有界轮次，并受代表级短期开关控制。
- `CONTACT_SHARED` 使用独立规范身份作用域和版本化同意：匿名、冲突身份、同意缺失、旧披露合同或历史未版本化同意保持渠道隔离；授权撤回后立即禁止召回并异步删除共享投影，重新授权产生新的同意版本。
- 使用账本继续区分 `SEARCH_HIT`、`SCOPE_ALLOWED`、`SAFETY_ALLOWED`、`PROMPT_INCLUDED` 和 `PUBLICLY_CITED`。

退出条件：Web、Matrix、Telegram 的 2 个代表 x 2 个联系人隔离矩阵通过；未披露、错误绑定、首条排除消息、跨渠道共享和跨联系人污染均确认零召回、零提取和零越权 Provider 结果；短期内容从不进入 OpenViking。

### R4：唯一设置入口与旧 UI 退役

- 在代表 Memory 配置页实现基础策略、渠道能力、保留策略和只读高级诊断。
- 删除顶层“记忆系统”导航、页面挂载、Owner 候选/条目/使用/操作控制台和“打开记忆系统”跳转。
- 旧 `view=memory` 深链在兼容期内只重定向到当前代表的 Memory 配置，不再渲染旧页面。
- 移除记忆批准、拒绝、纠正审批等人工动作；设置保存保持乐观并发、幂等、审计和 `private, no-store`。

退出条件：Owner 只能从选定代表配置记忆，界面不存在候选审批或虚假操作按钮，知识库和通用 Approvals 均可正常访问。

### R5：投影、清理与对账加固

- 每个长期记忆版本使用 `provider + versionId + contentHash` 幂等投影；旧 job 不能覆盖新 active version。
- 部分失败只重试失败项，停用/删除优先本地阻断；健康服务下远端物理清理建议在 60 秒内收敛。
- 到期 `ARCHIVE` 和 `DELETE` 由独立 lifecycle lane 执行；缩短保留期会同步压缩既有有效记忆的最晚保留时间。
- 因策略停用形成且没有删除证明的投影可在重新启用后严格重建；显式删除、到期删除和普通失败项不会被复活。
- 定期核查已知精确 URI 的缺失、哈希漂移和旧 active pointer。Provider 无完整稳定库存能力时，对账必须标记 `PARTIAL`，不得误报完整健康或模糊删除远端对象。

退出条件：投影可从 PostgreSQL 重建，失败可重试，删除证明不含正文，对账覆盖范围在设置中如实展示。

### R6：冗余代码清理

- 在所有调用迁移并稳定一个发布周期后，删除仅服务于人工记忆审核的页面、API、action、权限、DTO、样式、测试、worker 分支和新写逻辑。
- 历史审核表、枚举和兼容读取先标记 deprecated；确认线上无回滚依赖并完成数据归档后，再通过独立 migration 删除。
- 删除后运行静态引用扫描和全仓回归，确认不存在死路由、孤儿类型、无调用导出或错误导航。

退出条件：记忆人工审批代码无生产调用；保留的服务端治理能力均有明确消费者和测试。

### R7：灰度与完成门禁

- 内部代表（提取和决策审计开启、长期注入关闭）-> Web 小流量 -> Web 全量。
- Matrix 已具备首次披露、身份、provider edit/redaction、渠道内精确删除和隔离门禁；Telegram 已具备首次披露、身份、`edited_message`、`/forget`、`/delete_memory` 与精确删除命令，但 Bot 不可观测普通客户端消息删除。两渠道按代表开关独立灰度；功能关闭或门禁证据缺失时保持零召回、零提取、零越权 Provider 结果。
- 任意跨范围泄漏、敏感内容激活、删除后召回、错误公开来源或交易/权限依赖记忆，立即停止灰度。

## 6. 迁移与回滚

1. 数据库先加后减：自动策略记录和设置字段已上线；旧审核数据仅作只读审计，至少一个稳定发布周期后再独立删除废弃结构。
2. 运行时只信任自动策略：旧人工授权不再参与投影、召回或模型注入；不满足当前自动策略的历史记忆立即停止召回并等待重新提取。
3. UI 已删除旧顶层记忆、审核和“养成”页面与路由，只保留“数字代表 → 配置 → Memory”。
4. 回滚只允许关闭自动提取/长期召回并降级为无记忆回答，不能恢复新的人工审批、解除隔离、复活旧版本或撤销删除证明。
5. OpenViking 不作为回滚源；应用或 Provider 回滚后，从 PostgreSQL 当前有效版本重新投影。
6. 任何数据库下行迁移都不得让已阻断、过期、删除或撤回同意的记忆重新可召回。

## 7. 删除边界

| 处理 | 范围 |
| --- | --- |
| 删除 | 顶层记忆导航/页面、候选审批 UI、人工批准/拒绝记忆 API、新的人工作业分支、无调用 DTO/样式/测试 |
| 兼容后再删 | 历史 `MemoryReviewDecision` 数据结构、旧状态枚举及迁移审计数据 |
| 永久保留 | 候选隔离、安全分类、不可变版本、自动策略审计、使用账本、删除证明、投影任务、对账和运行时范围栅栏 |
| 不得改动 | 知识库及公开知识发布链路、通用 Approvals、交易/钱包/授权实时 PostgreSQL 读取、Inbox 原始会话产品 |

## 8. 非目标

- 不提供 Owner 逐条浏览、编辑或审批所有联系人记忆的工作台。
- 不把公开知识、知识草稿或发布版本迁入记忆模型。
- 不让 OpenViking URI、Score、Layer、Agent ID 或 Target URI 成为普通 Owner 的可编辑业务字段。
- 不用记忆决定付款、余额、退款、权益、访问授权或身份真实性。
- 跨渠道共享只开放给同一代表下、映射到同一已验证身份且由联系人明确授权的 Web、Matrix、Telegram 私聊；不会共享原始会话、身份字段、支付与权限事实，也不会跨代表或跨联系人。
