# Test Plan: Phase 0/1 Multi-Provider Sandbox

Generated by `/plan-eng-review` on 2026-08-28
Branch: `codex/dashboard-optimization`

## Affected Routes and Processes

- Compute session creation — runtime class remains server-derived.
- Compute lease acquisition — existing identity pins override current routing.
- Sandbox cleanup — stop/delete uses the stored provider.
- Compute execution — provider contract enforces cwd, timeout, output limits, and typed failures.
- `/health` — remains process liveness.
- provider readiness snapshot — reports configuration and remote capability degradation without secrets.

## Key Interactions

- Create new allowlisted Tencent and Daytona test identities in the same deployment.
- Reuse an existing identity after changing the routing override.
- Disable new identities for a provider while continuing an existing pin.
- Stop, restore/recreate, execute, and delete a provider runtime.
- Reject a non-test representative before identity insertion.
- Reject browser runtime in Phase 1 manual mode.

## Edge Cases

- Duplicate or malformed routing JSON.
- Rolling deployments with conflicting routing documents.
- Concurrent identity insertion.
- Identity archived/deleted during remote start.
- Definite versus ambiguous provider-create failure.
- Provider timeout, throttling, authentication failure, vanished runtime, and malformed response.
- Independent stdout/stderr byte limits and invalid UTF-8.
- Stale readiness cache and single-flight refresh.
- Missing adapter for an existing pinned provider.
- Reconciler owner crash and journal lease expiry.
- Secret canaries in provider errors and output.

## Critical Paths

1. Existing identity lookup → stored provider → same-provider lease → execution.
2. Absent identity → test eligibility → manual routing → conflict-safe insert → durable create journal → fenced bind → execution.
3. Ambiguous create → UNKNOWN → quarantine/reconciliation → never execute before BOUND.
4. Archive race → lifecycle epoch mismatch → remote cleanup/quarantine → explicit concurrent-change error.
5. Provider outage → typed pinned-provider error → no Docker or cross-cloud fallback.

## Required Test Layers

- Vitest unit tests for configuration, routing, registry, provider adapters, errors, and journal transitions.
- Shared provider contract tests for Docker, Daytona, and Tencent fakes.
- PostgreSQL integration tests for unique races, row locks, lifecycle epoch, and journal reclaim.
- Explicit live smoke tests for Tencent/Daytona only when external credentials are configured.
- Full repository typecheck and test suite before final review.
