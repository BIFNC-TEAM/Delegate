# Notion OAuth 导入

入口：仪表盘 → 知识库 → 导入知识 → 第三方导入 → Notion。

## 用户流程

1. 点击“连接 Notion”，在独立的 Notion 授权窗口选择工作空间和允许读取的页面。Delegate 不接收 Notion 密码。
2. 授权窗口返回后自动关闭，导入窗口保留当前选择和上传队列。
3. 页面列表自动汇总已授权页面及数据库记录，只读取元信息。用户直接勾选具体笔记，无需手动展开数据库。
4. 默认只导入勾选页面。开启“导入页面时自动导入其子页面”后，先展开并确认完整选择，再读取正文；可以取消不需要的子页面。链接到的数据库视图不会随之展开。
5. 点击“上传所选文件”，只读取选中的正文并加入现有上传队列；预览、可见范围、标签、代表关联和“开始上传”沿用原流程。
6. 权限不足或不支持的块会标记内容不完整，等待用户重新读取或明确选择“仅导入已读取内容”。完整页面不被其他页面的失败阻塞。

连接按工作空间保存，支持多个工作空间。每次授权有效期为 7 天，刷新令牌不会延长这 7 天；重新授权会重置期限。过期清理或主动断开只删除连接，不删除已经导入的知识。

## 内容范围

- 普通页面、数据库记录：标题、可读属性和正文转换为 Markdown。
- 标题、段落、列表、待办、代码、引用、折叠块、分栏、普通表格、公式等保留可读内容。
- 同步块：读取官方 API 允许读取的块内容，形成静态副本，不扩展到来源页面其余内容。来源不可读时标记不完整。
- 子页面：默认仅保留链接；只有开启包含子页面并确认选择后才单独读取。
- 页面引用、关系字段、数据库视图：保留引用；不自动读取目标页面或整库。
- Formula/Rollup：保存 Notion 返回的计算快照，不自行计算。读取分页属性，结果仍不完整则提示。
- 附件保留描述，外部嵌入保留链接；不下载附件正文，不抓取外部网站，不读取评论。
- 重复文件处理直接使用现有上传接口的三种策略：默认跳过完全重复内容、始终保留新副本、覆盖已有文件。导入后不自动同步。

## 服务端配置

参考根目录 `.env.example` 的四项配置：

| 变量 | 用途 |
| --- | --- |
| `NOTION_CLIENT_ID` | Notion OAuth 应用 ID |
| `NOTION_CLIENT_SECRET` | 应用密钥，只放服务端 |
| `NOTION_REDIRECT_URI` | 必须与 Notion 中登记的回调地址完全一致 |
| `NOTION_CREDENTIAL_KEY` | 独立的 32 字节 Base64 密钥，用于加密保存授权凭据 |

本地开发配置可以写入不受 Git 管理的 `apps/web/.env.local`。默认回调为 `http://localhost:3001/api/dashboard/notion/callback`，因此浏览器也应使用 `localhost:3001`，而不是 `127.0.0.1:3001`。

线上部署使用对应站点的 HTTPS 回调；配置 Notion 应用后将上述变量注入 dashboard。Compose 已透传这些变量，修改环境变量后需要重新创建容器（`docker compose up -d dashboard`），单纯 restart 不会更新容器环境。原生开发服务修改环境变量后应重启。

Notion 应用只需读取内容；不需要更新、插入内容或评论权限。可以选择读取用户信息但不含邮箱。配置凭据后执行 `pnpm db:generate`、`pnpm db:deploy` 并重启 dashboard。新增数据库结构仅为两张连接/授权状态表，不修改现有知识数据。

## 实现位置

- `packages/web-data/src/notion/client.ts`：官方 API、版本、分页、限流退避、超时和取消。
- `service.ts`：OAuth 状态校验、加密凭据、工作空间隔离、7 天期限、刷新和断开。
- `content.ts`：页面列表、明确选择的子页面展开、块和属性转换。
- `apps/web/app/api/dashboard/notion/`：继承现有仪表盘身份检查的接口与 OAuth 回调。
- `apps/web/app/dashboard/knowledge-notion-import.tsx`：连接、选择、读取、缺失内容确认。
- 原有 `knowledge-assets` 上传接口：接收 Markdown，沿用权限、重复处理、存储和索引，只增加来源记录。

连接凭据 AES-256-GCM 加密，并绑定所有者及连接 ID。OAuth state 一次性、有效 10 分钟，绑定发起浏览器及当前所有者；回调只允许回到仪表盘。读取结束再次检查连接有效性，防止断开后仍返回在途内容。密钥不进入浏览器、导入文件或 Git。

如果服务器直连 Notion 不通，可以设置可选的 `NOTION_HTTPS_PROXY`。这只影响 Notion 请求，不更改项目其他请求的网络路径。Windows 浏览器能使用系统代理不代表 Node 自动使用它；本地可填写已有代理的 HTTP 地址。容器里不能直接把宿主机代理写成 `127.0.0.1`，应使用容器可达的地址。

## 验证

自动化用例位于 `packages/web-data/tests/notion-content.test.ts`、`notion-service.test.ts` 和 `apps/web/tests/notion-route.test.ts`。它们覆盖选择边界、同步块权限失败、表格、属性分页、OAuth 重放/跨账号、到期/断开、刷新和接口身份检查。

真实联调应在只包含测试内容的已授权页面上完成：授权 → 列表 → 选一篇 → 预览 → 上传 → 索引完成 → 再次导入跳过重复。复杂权限场景（例如来源未授权的同步块）仍需对应真实样例核对官方返回行为，不能用模拟测试替代这个结论。

2026-10-27 本地联调：用户在内嵌浏览器完成真实 OAuth 授权，成功列出授权的笔记数据库及两篇记录。只选择“你的入门技巧”后完成预览、上传和 OpenViking 索引；再次导入相同内容显示“内容完全相同，已跳过”，知识库仅增加一份文件。此次索引耗时约 5 分钟，发生在现有 OpenViking 处理阶段。未改动 Notion 原始页面。

相关 12 个测试文件共 114 项通过，web-data/dashboard 类型检查、Prisma 校验及 Compose 配置校验通过。复杂同步块权限场景目前覆盖的是模拟官方响应测试，尚未具备真实样例逐项验证。
