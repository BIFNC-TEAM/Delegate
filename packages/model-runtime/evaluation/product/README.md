# 首批10条真实产品自动验收

这个入口实际请求隔离服务13002，通过SSE收取答案，再从15432读取同一run的发布版本、真实调用事件、知识注入/引用账本。动态内容由独立语义评审器判断，硬条件由程序断言。它不直接调用Agent运行时，不使用预填模型响应，也不依赖手工登记PASS名单。

正常Agent服务不导入此目录。只允许固定合成测试代表 `qa-agent-v2-product10-20261023`、所有者 `qa_agent_v2_product10_20261023`。不会修改3002、主库、旧测试代表或生产默认入口。

## 可重复执行

先提供受限环境配置（本地.env或进程环境，不要提交密钥）：

| 配置 | 必须满足 |
| --- | --- |
| `AGENT_TEST_DATABASE_URL` | PostgreSQL，127.0.0.1:15432，库名delegate；禁止连接选项/其他端点 |
| `DATABASE_URL` | 不设置或与上述值完全相同，冲突立即拒绝 |
| `OPENVIKING_BASE_URL`、`OPENVIKING_INTERNAL_BASE_URL` | http://127.0.0.1:11933 |
| `COMPUTE_BROKER_URL` | http://127.0.0.1:14010 |
| Broker、OpenViking、对象存储的必要凭据 | 沿用现有隔离栈配置；凭据不进入报告 |
| V2模型连接 | 与semantic试点评审器一致；不以模型名推断端点或密钥 |
| 独立评审连接 | 可配置 `DELEGATE_EVAL_JUDGE_BASE_URL/ID/API_KEY`，三者必须同时提供；否则显式使用 `--same-model-judge` |

本机使用198.18.0.0/15 DNS代理地址时，准备进程需沿用隔离栈既有的 `DELEGATE_ALLOW_DOCKER_DESKTOP_MCP_DNS_PROXY` 设置。这是已有受限代理处理，不应开启允许任意私网目标的测试开关。

```sh
# 离线机制与类型检查，不调用模型或外部服务
pnpm test:agent:v2:product
pnpm typecheck:agent:v2:product

# 首次准备专用合成代表、发布资料和同步工具目录；不执行用例
pnpm eval:agent:v2:product -- --live --prepare-only --same-model-judge

# 一条命令准备（已发布则只核对）并执行三轮
pnpm eval:agent:v2:product -- --live --prepare --same-model-judge --repetitions=3

# 单项复测，仍保留该用例的全部变体
pnpm eval:agent:v2:product -- --live --same-model-judge --ids=V2-013 --repetitions=3
```

依赖现有隔离栈已启动；命令不启动、重建或部署服务。创建仅限该命名空间；已发布夹具不会被重复seed覆盖。原始资料、政策版本和失败记录保留，不清空数据库。

## 用例与执行顺序

[cases.ts](cases.ts)为这批可执行输入和判定标准，不从MD解析生成。100条MD仍是需求规格，二者不能混淆。

| 用例 | 变体数 | 本批输入范围 |
| --- | ---: | --- |
| V2-001 | 1 | 新会话问候 |
| V2-002 | 2 | 身份能力介绍、明确询问AI/真人 |
| V2-003 | 2 | 英文、混合语言要求中文 |
| V2-004 | 1 | 三条、每条不超过20字符的公式解释 |
| V2-005 | 3 | 翻译、润色、两句摘要 |
| V2-007 | 2 | 缺城市、催促但仍缺城市 |
| V2-011 | 3 | 一个方案空缺、两个均缺、材料完整 |
| V2-013 | 1 | 缺城市→上海，同一会话两轮 |
| V2-020 | 2 | 年假制度、差旅制度及真实引用 |
| V2-031 | 1 | 内部奖金无依据，不用互联网填造 |

共18个变体，每轮19次聊天；三轮54个判定单元、57次聊天请求。每个变体使用新cookie，只有同一变体内的澄清恢复保留cookie。评审针对一个变体完整对话一次调用；Agent本身可能有多个模型步骤，计量分开。

## 代码链

1. [scope.ts](scope.ts)：固定API/DB范围和预算；检查浏览器、exec、read、write、process均为DENY。
2. [store.ts](store.ts)的`prepare/preflight`：创建或核对专用代表、发布知识、工具目录与权限；不调用云沙盒。MCP启用是因为当前产品共用compute开关；其他能力显式DENY，sandboxTestEligible=false。单次MCP预计1000 tokens，测试代表自动批准阈值设1000，避免只读验收进入不支持的审批等待。
3. [client.ts](client.ts)的`turn`：真实GET/告知协议/POST入队/SSE终态，cookie只发送到固定测试服务。不重试未知网络失败或已准入任务；只有明确HTTP429可以有限等待重试。
4. [store.ts](store.ts)的`observe`：按API返回runId查询，同步核对代表/所有者/发布版本；读取真实知识授权、注入和引用记录。知识必须属于同一发布版本且hash/授权检查一致。
5. [cases.ts](cases.ts)的`assertProductStep`：核对任务状态（不是仅看交付COMPLETED）、工具轨迹、实际引用、格式、澄清恢复的任务ID和累计预算。
6. [cli.ts](cli.ts)：组合可信发布配置、参考资料、实际注入资料、真实MCP回执和对话，调用[独立语义评审器](../semantic/engine.ts)。MCP正文通过同一访客的授权下载接口读取，不绕过下载权限。
7. `finalVerdict/reportExitCode`：自动汇总逐变体与逐用例结果。任意硬失败不可被语义pass覆盖；评审异常、证据不足或未执行保持review。全部必测变体、重复轮次满足要求才把该用例记pass。

## 可信依据与数据最小化

- 发布身份和当前测试所有者配置、该版本的公开资源清单，为参考事实。
- 实际知识注入账本单列，不能把“资料库有内容”冒充“本轮检索并使用了内容”。引用存在也不自动等于支持结论，仍需语义核对。
- 天气使用真实只读MCP，温度不写死在断言中；必须有成功forecast调用及真实回执支持。
- 只读公开搜索工具已注册并可发现；内部未命中用例要求不得把公开资料当作内部奖金依据。
- 不默认保存完整工具返回。MCP回执最多8份、单份128KB，报告只留最多6000字符摘录、hash和截断标记；关键证据不完整时不能凭猜测通过。
- 不保存cookie、告知证明、隐藏思考或凭据。只处理专用合成业务数据，不开放任意代表/生产数据导入。

## 输出、版本和失败

报告保存在 `reports/agent-v2/product10/`，每次唯一文件名。包含运行服务容器ID/镜像、执行器hash、实际发布版本、输入、run/trace/task ID、答案、硬断言、语义逐项理由、工具证据、调用用量和最终安全检查。记录运行镜像，不把工作区源码当成已部署代码。

退出码0=全部完成并通过，1=有失败，2=待复核/缺配置/不完整。准备模式的0只表示夹具就绪，不表示测试通过。失败记录不可被重跑覆盖；修正测试规则时必须保留父报告和差异，不能删掉失败提高通过率。

初始测试护栏在scope.ts集中：每个HTTP请求150秒、响应2MB、最小提交间隔2.5秒、准入限流最多重试2次；每批最多96次评审、400000 token预算。评审请求自身仍遵守semantic引擎的30秒/输入24KB/输出1800tokens限制。这些不是性能SLO；性能验收继续待定。

Ctrl-C停止新请求和本地等待，保留已准入runId；服务器端可能按其自身时限完成已受理请求，不能把断开SSE当作服务端已取消。未完成不计通过，不自动重发。

本批不认证所有100条，也不覆盖沙盒、真实写入、多渠道或负载性能。正常Agent架构不因测试评审器而改变。

## 保存证据的离线重算

若修正了程序断言，可以使用：

```sh
pnpm eval:agent:v2:product:recheck -- reports/agent-v2/product10/<原始有效报告>.json
```

仅允许本报告目录内的有效产品报告；核对输入/用例/版本和安全检查，保留原硬断言、原语义判定与父文件hash。它不发送聊天请求、不调用评审模型、不把待复核语义结果改成通过；报告明确标为离线重算，不能当新一轮执行。20261023这次重算只撤销了缺方案变体额外添加的“禁止RAG”约束。具体结果与已知问题见[本批报告](../../../../reports/agent-v2/product10/report-20261023.md)。
