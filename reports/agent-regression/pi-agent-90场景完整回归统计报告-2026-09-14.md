## 七、5 条失败详情

### SKILL-04：坏单元格识别

- 结果：FAIL，124,360.1 ms；20 次模型调用，18 次工具调用。
- 预期：识别 `O1003.quantity` 的异常值，并明确给出排除异常行后的临时净额 1100。
- 实际：多次生成未满足校验条件的沙盒代码，达到 20 步上限；最终没有可靠指出坏单元格。
- 分类：**可重复的模型流程可靠性缺口**。完整运行失败后单项复测仍失败。

### BOX-02：CSV 汇总产物

- 结果：FAIL，138,086.8 ms；14 次模型调用，13 次工具调用。
- 实际：沙盒多次失败后，模型试图用聊天代码块代替真实文件，运行时最终取消，没有可下载的正确 CSV。
- 分类：**模型路径波动**。随后同代码单项复测通过，真实生成 `city_net_sales_summary.csv`，深圳/上海/广州分别为 850/300/200。

### BOX-06：错误脚本修复

- 结果：FAIL，69,461.7 ms；20 次模型调用，20 次工具调用。
- 实际：没有稳定遵循“先原样执行 buggy.py 获取真实失败，再修复重跑”的顺序。
- 分类：**模型路径波动且重试成本高**。随后单项复测通过，保留初次错误 span，并在修复后真实输出 1350。

### FLOW-05：报告与 CSV 双产物

- 结果：FAIL，175,846.2 ms；15 次模型调用，14 次工具调用。
- 实际：多次生成包含占位符或未读取附件的脚本，最终超时取消，没有交付两个一致产物。
- 分类：**模型路径波动且重试成本最高**。此前同代码单项复测通过，真实交付 `report.md` 和 `summary.csv`，两者均包含总额 1350 与城市值 850/300/200。

### FLOW-07：CSV 成功后图表失败

- 结果：FAIL，19,950.7 ms；5 次模型调用，4 次工具调用。
- 实际：CSV 已正确生成，但模型没有继续触发受控图表失败步骤，因此没有完整验证“部分成功”表达。
- 分类：**模型路径波动**。此前同代码单项复测通过，保留正确 CSV，并准确说明图表失败且未生成 PNG。

## 八、修复与复测记录

1. 删除隔离种子脚本中已经退役的 `delegation*` 数据库字段，并增加防回归测试。

3. Pi 自包含 Python、JavaScript 和 Shell 程序携带当前用户请求哈希与代码哈希；Broker 重新解码并验证后，才允许在已发布 `ALLOW` 策略下免除“复杂 Shell”误审批。

5. 多轮实时问题在模型跳过工具时增加一次有界取证纠正，CHAT-01 随后通过。
6. Skill 识别同时读取 `id/slug/name/displayName/description/capabilityTags`，避免已加载 Skill 被误判为未加载。
7. 表格恢复程序使用数据库声明的 collision-safe 沙盒路径，不再由公开文件名重建路径。
8. 符合版本固定内置表格 Skill 的任务执行服务器验证程序，避免模型临时代码绕过真实文件读取。

## 九、性能与优化结论

本轮没有传入同模式基线，因此不能报告整体性能提升或退化；性能结论保持 `NOT_DETERMINED`。

有实测依据的后续优化建议：

1. 为“坏单元格识别”增加版本固定、服务器验证的数据质量执行模板，避免依赖模型反复尝试同一校验。
2. 相同确定性沙盒错误连续出现两次后，应停止继续生成近似代码，转入已安装 Skill 的受控恢复或明确失败，可显著降低 60–175 秒长尾。
3. 将双产物报告要求表达成结构化产物契约，由运行时验证文件集合、占位符和交叉一致性，而不是完全依赖自然语言提示。
4. 模型生成是主要耗时来源：`model/generate` p95 为 12,079.6 ms，而知识、Skill 和大多数 MCP 调用远低于模型耗时。优化优先级应放在减少重复模型轮次，而不是压缩知识检索时间。
