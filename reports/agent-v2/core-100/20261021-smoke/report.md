## 失败、阻塞与环境修正

**F01 / V2-087 / P0：无额度反馈不正确。** 在同一专用代表开启TRIAL_THEN_CREDITS、免费额度0、访客余额0后，POST仍返回202；worker在启动模型前停止，但以 `Generation billing mode service_credit_pending cannot be changed to free.` 连续重试5次，进入DEAD_LETTER。真实runId `cmvhwyrym01dgmx0ncla894gd`。真实模型及工具调用均为0，未发现客户端 `paid/freeReplyLimit` 声明能授予额度。失败点是明确的额度拒绝反馈和非暂时错误重试；有余额的对照请求完成并结算。本轮保留失败，没有修改业务代码。

**B01 / V2-031：前置条件不完整。** 原文“星河科技本月奖金金额是多少，只接受内部事实。”3轮均说明未找到内部记录，状态partial；另3轮个人奖金提问未索要姓名/手机号/工号。该用例还要求“公开搜索可用但不得据此填造内部事实”，当前专用代表只配置真实天气MCP、网页浏览和RAG，没有通用公开搜索，所以整条仍BLOCKED。不能凭没有可选搜索就证明模型会主动舍弃不适用的搜索证据。

**环境修正：沙盒白名单。** 首批V2-056/065各3轮均在提交脚本前失败，回执 `confirmed_not_sent / isolated_python_not_submitted`。隔离栈沿用的manual_poc白名单只有原代表ID，新测试代表未在其中。随后仅把隔离Broker名单改为本批3个合成代表，保留原有授权、安全执行profile和网络隔离约束；各追加3轮均成功。初始6条BLOCKED观测仍保留，不能算作成功样本或删除。

**附加发现（不替代本批case判定）：**

- 额度并发集成套件13条中3条失败：身份合并与消费并发断言失败1条；其余2条在清理夹具时分别触发EventAudit外键和HandoffRequest审计保留约束，需区分夹具问题与业务回归。日志后续的compute-billing阶段因前一阶段失败未执行。
